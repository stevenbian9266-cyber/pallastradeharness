## 1. 背景与目标

- **背景**：引擎的任务/门禁闭环完善，但缺少设计文档 §15 的"总前置条件"——项目开始前必须有项目画像（project.yaml）并锁定治理版本；任务应记录所用治理版本。当前没有任何治理版本概念。
- **目标**：实现项目画像 + `governance_ready` 判定 + 治理版本锁定 + 任务绑定治理版本。
- **成功指标**：`harness governance:init` 建画像；`governance:status` 如实报告未就绪项；`governance:version` 锁定 `governance-0.1.0`；`task start` 在就绪项目上记录治理版本。

## 2. 用户故事 / 场景

- 作为 引擎使用者，我希望项目开始前先建立项目画像并锁定治理版本，以便"先确定如何工作，再让 AI 按规则工作"。
- 作为 引擎使用者，我希望 `governance:status` 用大白话告诉我还缺什么，而不是要我理解内部字段。
- 场景：正常（完整画像 → ready → 锁定版本）、边界（缺字段 → 未就绪并列出缺失）、异常（未就绪强行锁版本 → 拒绝）。

## 3. 功能需求（FR）

- FR-001：新增 `bin/governance.mjs`：`validateProfile`（name/mode/status/risk_domains/skills/prd_category/coding_policy/style_policy + blocking_conflicts）、`governanceReady`（缺失项清单）、`readProfile`/`writeProfile`（`harness/project.yaml`）、`lockVersion`（`harness/governance/versions/<v>.json` 快照 + 回写 profile）、`listVersions`。
- FR-002：CLI `harness governance:init [--name <n>] [--mode greenfield|existing]` 建画像草案（status=governance_setup_required）。
- FR-003：CLI `harness governance:status [--json]` 输出 ready 或缺失项（大白话）。
- FR-004：CLI `harness governance:version [--version <v>]` 仅当 ready 时锁定（默认 governance-0.1.0），未就绪拒绝。
- FR-005：`task start` 在项目 governance_ready 时把 `governance_version` 写入任务（§15.9 任务记录治理版本）。
- FR-006：`config.governance` 默认（profileFile / versionsDir）。

## 4. 非功能需求（NFR）

- 向后兼容：无 project.yaml 的项目行为不变（governance_version 为 null）。
- 确定性：纯函数 + 本地存储，可测试；状态机只前进（锁定版本不可覆盖）。
- 大白话：status 输出面向人的描述，内部字段进 JSON/技术详情。

## 5. 验收标准（AC，与测试一一映射）

- AC-001 ← FR-001：合法画像通过校验；缺 name / 非法 mode / 非法 status 被拒绝。
- AC-002 ← FR-001：`governanceReady` 对缺字段画像返回缺失清单，对完整画像返回 ready。
- AC-003 ← FR-001：writeProfile → readProfile 往返正确（临时目录）。
- AC-004 ← FR-001：lockVersion 生成版本快照 + 回写 profile；重复锁定同版本被拒绝。
- AC-005 ← FR-003/004：CLI `governance:status`（未就绪列出缺失）与 `governance:version`（就绪后锁定成功）。
- AC-006 ← FR-005：governance_ready 项目上 `task start` 的任务含 `governanceVersion`。

## 需求标题

交互式 TUI 当前任务视图：在现有静态 dashboard 之上增加键盘导航、任务详情查看与动作执行，所有动作均有 CLI/JSON 等价命令。

## 任务类型

功能优化（方案既定任务 HTH-016）

## 需求描述

给 `harness tui` 增加交互模式：
1. 任务列表可键盘导航（↑/↓ 移动光标、Enter 查看详情、r 刷新、q 退出）
2. 任务详情视图：id / title / status / risk / evidence 数 / nextAction / goals / acceptanceCriteria / blockers
3. 在详情中可直接执行 nextAction（用户确认后运行对应 CLI 命令）
4. 非 TTY 环境保持现有静态输出 + `--json`（等价物）

## 技术方案（初步）

- `bin/tui.mjs`：
  - 提取纯函数 `buildTaskDetail(task, evidence)`（可测）
  - 交互循环用 `node:readline`（跨平台，Windows/macOS/Linux 一致），TTY 检测 + 非 TTY 回退静态
  - 动作执行 = 复用 `nextAction` 生成的 CLI 命令，用 `spawnSync` 运行并回显输出
- `bin/tui.test.mjs`：补 `buildTaskDetail` 断言 + 非 TTY 回退断言
- `docs/getting-started.md`：追加交互式 TUI 使用说明

## 风险点

- Windows 终端原始键盘（setRawMode）兼容性 → 用 readline 规避
- 交互循环阻塞 CI/管道 → TTY 检测回退静态输出

## 验收标准（对齐方案 HTH-016）

- [ ] 所有交互操作（查看详情/执行动作/刷新/退出）均有 `harness <cli>` 或 `--json` 等价命令
- [ ] TTY 下可键盘导航并查看任务详情；非 TTY 下输出静态 dashboard 不崩溃
- [ ] `node --test bin/*.test.mjs` 全绿
